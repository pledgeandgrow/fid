# determinism-allow.txt — the walks of a hash map and the random numbers the
# compiler may have (docs/roadmap/llvm-roadmap.md RL13; read by
# scripts/determinism-scan.py, run by scripts/determinism-check.sh).
#
# Every other call in compiler/*.fd (the "source" scan), or in the C of the
# compiler (the "c" scan), of HashMap_keys, HashMap_values, their _i forms,
# HashMap_to_str, p_map_keys, p_map_values, core's hm_* helpers or
# p_os_random_u64 fails the check: its order (or value) could reach the
# compiler's output. Add a line only with the reason the order cannot.
#
#   source <file> <function>   reason
#   c <function>               reason

# The interpreter (`fid run`) performs a program's own call of
# p_os_random_u64: the program's behaviour, not compiler output.
source compiler/interp.fd Interpreter_call_runtime   runs the program's call
c Interpreter_call_runtime                            runs the program's call

# `fid serve --port`: the access key written to the key file
# (serve_key_path); never part of what a request compiles.
source compiler/main.fd serve_socket   the serve access key
c serve_socket                         the serve access key

# core's own walks: each is the implementation of one of the functions the
# scan looks for (HashMap_values sorts by key through HashMap_keys, ...). A
# caller of any of them in the compiler is reported under its own name.
c HashMap_keys_i     core: HashMap_keys for integer keys
c HashMap_values     core: values in sorted-key order
c HashMap_values_i   core: HashMap_values for integer keys
c HashMap_to_str     core: printing a map (programs only)
