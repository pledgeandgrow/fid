# lane-skips.txt — tests a target cannot run by their nature, read by
# scripts/cross-test.sh (and so suite-all.sh and tier1.sh, PL2). Each is
# listed in the lane's results as "SKIP  <test> (<reason>)": not built, not
# run, not counted as passing. Tests that need an external library or a
# bare machine on every target stay in cross-test.sh's skip_re.
#
# One test per line: <targets> <test> <reason ...>
#   targets  a bash `case` pattern matched against the lane's target
#            (x86_64-linux, aarch64-macos, x86_64-windows-pe, ...);
#            a leading ! means every target the pattern does not match
#   test     the file's name without .fd
# A test is skipped only for what it cannot do on that target, never for a
# failure that could be fixed: those stay FAIL until they are.

# LG15: reads the export tables of C:/Windows/System32's DLLs
!*-windows*   test_cparser_dll_exports   reads the export tables of the System32 DLLs (Windows only)

# F9: WASI has no system crypto or TLS library (BCrypt / libcrypto /
# Schannel / OpenSSL), nor socket creation: compiler.fd c_platform_module
# has no WASI module for `crypto_bind` or `tls`
wasm32-wasi*  test_crypto_bind       needs the system's crypto library (BCrypt / libcrypto); WASI has none
wasm32-wasi*  test_crypto_bind_rsa   needs the system's crypto library (BCrypt / libcrypto); WASI has none
wasm32-wasi*  test_tls13_local       needs the system's TLS library and sockets; WASI has neither

# XT28: what WebAssembly under WASI preview 1 cannot do (scripts/wasm-test.sh
# matches these against its lane, wasm32-wasi-native; cross-test.sh's
# wasm32-wasi, the C path, has the same limits)
wasm32-wasi*  test_asm_c             its main is @cfg(arch = "x86_64"): x86-64 inline assembly through the C compiler; a wasm32 build has no main
wasm32-wasi*  test_dynlib            loads a C library at run time (dlopen / LoadLibrary); WASI has no loader and no C libraries
wasm32-wasi*  test_dlsym_typed_call  calls C functions it finds at run time (p_dl_find); WASI has no loader and no C libraries
wasm32-wasi*  test_dl_find           loads a C library at run time (p_dl_open / p_dl_find); WASI has no loader and no C libraries
wasm32-wasi*  test_process_spawn     starts child processes; WASI preview 1 has no processes
wasm32-wasi*  test_process_pipes     starts child processes with pipes; WASI preview 1 has no processes
wasm32-wasi*  test_signal_flags      raises signals in the process; WASI preview 1 has no signals (raise / kill are ENOSYS)
wasm32-wasi*  test_prof_sampling     FID_PROF samples on SIGPROF from a watcher thread; WASI preview 1 has neither signals nor threads
wasm32-wasi*  test_runtime_connect_retry  opens and connects TCP sockets; WASI preview 1 cannot create sockets
wasm32-wasi*  test_c_callback_user_data   hands a Fides callback to the C library's qsort_s / qsort_r (one @cfg variant per OS); WASI has no C library
wasm32-wasi*  test_stdlib_udp_addr   stdlib/udp.fd has @cfg variants for Windows and Unix sockets only; WASI preview 1 has no sockets, so the module does not build
wasm32-wasi*  test_unix_socket       binds and connects AF_UNIX sockets; WASI preview 1 cannot create sockets
wasm32-wasi*  test_ws_local          a WebSocket over a local TCP connection; WASI preview 1 cannot create sockets
wasm32-wasi*  test_stdlib_http_binary  HTTP over a local TCP connection (p_co_connect); WASI preview 1 cannot create sockets
wasm32-wasi*  test_task_park_wake    tasks parked on a listening TCP socket (p_co_accept); WASI preview 1 cannot create sockets
wasm32-wasi*  test_task_interleave   its part 7 spawns a thread that waits for a channel main fills afterwards; under WASI preview 1 a thread runs to its end when it starts (no shared-memory threads), so it waits forever
wasm32-wasi*  test_alloc_owner_return  a producer and a consumer thread take turns on a shared word; under WASI preview 1 a thread runs to its end when it starts (no shared-memory threads), so the first one waits for the other forever
