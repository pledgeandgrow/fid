## par_map

Map: `out[i] = f(v[i])` for every element, in order. Sequential: a
function value cannot go to another thread (BG256, the module's
header).


*Example -- run as a test by `scripts/doctest.py`:*

```fides

var sq = par_map(v, fn(x: i64) -> i64 { x * x });
```

## par_reduce

Reduce: fold all elements with `f`, seeded with `init`, left to right.
Sequential, as par_map (the parallel path folded two halves, each from
`init`, and combined them with f: the same result for an associative f

## par_fill

Parallel fill: fill a Vec with a constant value.
Currently sequential — each element is independent (embarrassingly
parallel) but parallel write to a shared result Vec requires
finer-grained synchronization.


*Example -- run as a test by `scripts/doctest.py`:*

```fides
val f = par_fill(4, 7);
assert_eq(f.len(), 4);
assert_eq(par_sum(f), 28);
val r = par_range(1, 5);
assert_eq(par_sum(r), 10);
assert_eq(par_dot(r, r), 30);
var sq = par_map(r, fn(x: i64) -> i64 { x * x });
assert_eq(sq.get(3), 16);
```
