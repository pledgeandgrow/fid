## P0 — Silent miscompilation and security

These produce wrong output or exploitable behaviour with no diagnostic.

### P0-1. PE `p_print_int` clobbers digits 5–8 — **VERIFIED**, S
- `src/pe.rs:4922` (`gen_print_int`), `compiler/pe.fd:2418` (`PeCodeGen_gen_print_int`).
- The digit buffer ends at `rbp-24` and grows downward (`lea r8, [rbp-24]`, `dec r8` per digit). The `WriteFile` `&written` slot is `lea r9, [rbp-32]` and is zeroed with a 4-byte store before the call, i.e. bytes `rbp-32..rbp-29` — exactly digits 5–8 counted from the end.
- Repro: `println(12345678)` → `\0\0\0\05678`; `println(12345)` → `\02345`. Any integer with ≥5 digits is wrong in every `fidesc emit` / `build --target x86-64-windows` binary. This alone explains several of the 73 PE output diffs (Appendix A).
- Fix: put `written` at `rbp-72` (the frame reserves 80 bytes). Same layout in both ports.

### P0-2. PE f-string / `p_to_str` prints negative integers as unsigned — **VERIFIED**, S
- `println(f"neg {0 - 5}")` → `neg 18446744073709551611` (interpreter: `neg -5`). `src/pe.rs` `gen_to_str` has no sign branch; `p_print_int` does. Port the sign handling.

### P0-3. Lexer: integer literals above `i64::MAX` become 0; malformed literals panic the compiler — **VERIFIED** (hex), S
- `src/lexer.rs:197,206,215` — `from_str_radix(..).unwrap_or(0)` for hex/bin/oct, so `0xFFFFFFFFFFFFFFFF` and `0xcbf29ce484222325` lex to **0**.
- `src/lexer.rs:250,265,268` — `.unwrap()` on decimal/float parse: `9223372036854775808` or `1e` crashes `fidesc` instead of reporting an error.
- Repro: `val a: i64 = 0xFFFFFFFFFFFFFFFF; print(a);` → `0`.
- Downstream: `stdlib/ota.fd:18,31` and `stdlib/storage.fd:29-33` use the FNV-64 offset basis `0xcbf29ce484222325` → every hash is computed from 0; bit masks `0xFFFF_FFFF_FFFF_FFFF` become 0. Check `compiler/lexer.fd` for the same pattern.
- Fix: parse as `u64`, reinterpret as `i64`; on failure push a diagnostic.

### P0-4. `random.fd` never advances: every `random_int` / `uuid_v4` returns the same value — **VERIFIED**, S
- `stdlib/random.fd:24` declares `pub const RNG_DEFAULT: RngState = RngState { state: 1 }` and `random_seed`/`next_raw` assign to `RNG_DEFAULT.state`. Consts are inlined at each use (`src/lower.rs` const inlining), so the store goes into a temporary.
- Repro (`use random; print(random_int(100))` ×3) printed the same number three times. `uuid_v4()` (`stdlib/uuid.fd:29`) is therefore identical on every call. `tests/bootstrap/test_new_stdlib.fd:136` only checks the range and doesn't catch it.
- Root cause is also a compiler bug: field assignment to an unresolvable/const target is silently dropped (`src/lower.rs:~2366`, see P0-24).
- Fix: module-level `var` (globals exist now), or pass state explicitly. Even then the LCG low bits are weak (`random_bool` strictly alternates; `random_float` can return 1.0) — M to move to xorshift/PCG.

### P0-5. C backend emits `v = (int64_t)&global` into a `void*` — **VERIFIED**, S
- `src/codegen_c.rs:1592`, `compiler/codegen_c.fd:2470`.
- `-Wint-conversion` is a hard error on clang ≥16 and gcc ≥14. Compiling the stage-1 compiler (`fidesc dump-c compiler/main.fd`, 30.5 MB) with `zig cc` (clang 20) fails with 20+ "incompatible integer to pointer conversion" errors; it only builds with `-Wno-error=int-conversion`. Any user whose `CC` is a current clang/gcc cannot use `ccompile` on code with globals.
- Fix: emit `(void*)&g` when the destination is a pointer, else `(int64_t)(intptr_t)&g`.

### P0-6. C backend: global initializers that aren't plain literals become 0 — **CONFIRMED**, S–M
- `compiler/codegen_c.fd:1886` (`is_simple_init_expr`), `:1915` (`gen_global_runtime_expr`) handles `IntLit/FloatLit/BoolLit/StringLit/MethodCall/StructLit`, everything else `_ => "0"`. A negative literal parses as `Unary(Neg, FloatLit)` and is never folded, so `stdlib/physics3d.fd:134 var g_gravity_y: f64 = -9.81` becomes `0.0`. Binary expressions, const references and calls also become 0. Struct-typed globals only get `memset(0)` (`:2079–2103`).
- Same class in the PE emitter: float/string/negative globals are zeroed, no `__init_globals` equivalent (`compiler/pe.fd`, grep `f64_to_bits is a stub` — stale comment, the function exists) — PLAUSIBLE.

### P0-7. Self-hosted `LoopVectorize` runs by default and skips 3 of every 4 iterations — **CONFIRMED**, S (disable) / L (real vectorizer)
- `compiler/opt.fd:137` puts `Pass::LoopVectorize` in `Pass_all()`. The pass (`opt.fd:~3780–4010`) only rewrites the induction increment `1 → 4` and emits no SIMD body, so a loop with constant trip count 12–64 (divisible by 4) over arrays executes a quarter of its iterations. It also overwrites a `ConstInt(1)` that CSE may share with other uses. `tests/selfhost/test_opt.fd:900` asserts the current (wrong) behaviour.
- Affects the self-hosted `--native` x86 path only. `LoopRotate` is already disabled in the same list for a similar reason.

### P0-8. `elf64.fd`: unknown mnemonic is emitted as `nop` — **CONFIRMED**, S (error) + M (encodings)
- `compiler/elf64.fd:1193`. `codegen_x64.fd` emits `jo` (every integer overflow check, `~904–918`), `movw` (16-bit stores), and `addpd/subpd/mulpd/divpd/movupd/movapd` (`~1815–1910`); none of these are encoded, so they are silently dropped. Native ELF binaries therefore have **no overflow checking** even though F64 says it's always on.

### P0-9. Native x64/ARM64/RISC-V/WASM: `GlobalAddr` emits `mov $0` — **CONFIRMED**, M
- `compiler/codegen_x64.fd:550` ("emit as zero for now"). Every read/write of a module-level global in a native build dereferences NULL. `docs/selfhost/known-bugs.md` 2b.3 records the same for ARM64/RISC-V/WASM.

### P0-10. Native runtimes: `p_vec_push` never grows the buffer — **PLAUSIBLE**, M
- `compiler/runtime_linux.fd` (`p_vec_push`, ~2177/2209), `runtime_arm64.fd:~484`, `runtime_riscv.fd:~528`: capacity is fixed at 509 elements inside one 4096-byte block; the 510th push overruns the heap.

### P0-11. Interpreter (`compiler/interp.fd`) diverges from compiled semantics — **CONFIRMED** (memset), PLAUSIBLE (rest), S each
- `:3875` `p_memset` returns the pointer and writes nothing — `stdlib/arena.fd:157,162` zero/fill memory with it.
- `:3887+` file I/O stubs: `p_file_read` → `""`, `p_file_exists` → false, writes → 0.
- Unknown runtime function → returns 0 and only logs under `-v` (grep `unknown runtime`); should be a hard error.
- No integer overflow checks; div/mod by zero yields `Void` instead of panicking (`~1640`). So `fides-c run` accepts programs that `build` rejects at runtime.

### P0-12. `ComptimeReflect` that reaches the lowerer becomes `ConstInt(0)` — **CONFIRMED**, S
- `compiler/lower.fd:5311`. Happens whenever `comptime_eval` didn't substitute it: the no-std pipeline never runs `comptime_eval`, and a generic `T` can survive into mono. `@size_of(T)` etc. silently become 0.

### P0-13. `Lowerer_infer_expr_ast_type` is defined twice; the simplified copy wins — **CONFIRMED**, S
- `compiler/lower.fd:6180` (full) and `:6807` ("simplified": returns `I64` for most expressions and `Ref(U8)` instead of `Str`). It feeds closure return-type inference, so `|x| x * 2.0` can be typed `I64`. Note `3cdf0fc` added cross-module duplicate detection in the Rust bootstrap, but these are in the same module (later definition wins).

### P0-14. A second `impl` block for an existing type is dropped — **CONFIRMED**, S
- `compiler/typechecker.fd:1054`: the "merge" branch is an empty comment. A second `impl Foo` in the same module, or a user `impl` on a stdlib type, loses its methods → spurious missing-method errors.

### P0-15. Unbound generic type params default to `i32` — **CONFIRMED**, S–M
- `compiler/mono.fd:1918`. A type parameter appearing only in the return type is instantiated as `i32` and truncates 64-bit results.

### P0-16. Generated C HTTP parser: remote heap overflow + header injection — **PLAUSIBLE**, M
- `src/codegen_c.rs` `p_http_parse_request` (grep; ~4735–4797 at `d8b3044`). Buffer `cap=1024`; a path near 1023 bytes plus method/version/JSON framing pushes `pos > cap`, `cap-pos` underflows as `size_t`, the next `snprintf`/`memcpy` writes past the heap block. No CRLF → `p = line_end + 2` reads past NUL. Method/path/header values are emitted into JSON without escaping, so a client can inject `"headers":{...}` and `p_json_get` returns the first match. Check the `compiler/codegen_c.fd` twin.

### P0-17. `sql_bind` permits SQL injection; `SQLString` guarantee isn't enforced — **PLAUSIBLE**, M
- `stdlib/typed_strings.fd:93` doubles `'` but never quotes the value: `WHERE id = ?` with `1 OR 1=1` injects. `p_string_replace` replaces every `?` (doc says first). `stdlib/db.fd:133 qb_param` concatenates raw values; `Database.query/exec` (`db.fd:25`, `sqlite.fd:152,214`) take plain `str`, so the "compile error unless SQLString" promise is void. `sqlite.fd` declares no `sqlite3_bind_*`.

### P0-18. HMAC-SHA256 is wrong on both backends — **PLAUSIBLE**, M
- `stdlib/crypto.fd:412` (`hmac`) round-trips bytes through `str_from_bytes` (`core.fd:2289`). Interpreter: bytes ≥0x80 become 2-byte UTF-8 (`src/interp.rs:2827`). C: a 0 byte truncates (`src/codegen_c.rs:3420`). `tests/bootstrap/real_crypto.fd` prints the HMAC but never asserts it. The header comment advertises SHA-512 and a CSPRNG that don't exist. Fix: a `Vec<u8>`-based `sha256_bytes`.

### P0-19. OTA firmware verification can be bypassed — **PLAUSIBLE** (+ VERIFIED root cause P0-3), S–M
- `stdlib/ota.fd:18,31,84`: a manifest labelled `sha256:` is compared against a 16-hex FNV-64 digest; the signature field is never checked; and because of P0-3 the FNV basis is 0 so the digest is constant.

### P0-20. Taint sanitizers can be fooled — **PLAUSIBLE**, M
- `path_safe` (`stdlib/typed_strings.fd:251`) only rejects `..`; absolute paths, `C:\` and backslashes pass (doc says absolute paths are rejected). The typechecker treats `path_normalize` as a sanitizer (`src/typechecker.rs:2979`) but `stdlib/path.fd:141` keeps leading `..`. Sanitizers match by name regardless of sink (`typechecker.rs:3287`): `html_escape(x)` passed to `sql_query` is accepted.

### P0-21. `@derive` generates fake output — **PLAUSIBLE**, M
- `src/compiler.rs:2056` `Serialize` returns the constant `{"a":0,...}`; `:2117` `Deserialize` ignores its input and returns a zero-filled struct; `Debug` prints `field: ?`.

### P0-22. PE runtime helpers return wrong values — **CONFIRMED** (vec_contains, vec stubs), PLAUSIBLE (rest), S each / M as a group
- `p_vec_contains`: the "found" compare jumps to `not_found`, which does `xor rax` → always false. `src/pe.rs:7438`, `compiler/pe.fd:5608`. Used by `vec.fd:85`, `stack.fd:66`.
- `compiler/pe.fd:5684–5716`: `p_vec_insert/remove/reverse/extend/sort` are `xor rax; ret` — `vec.fd:75–105` methods do nothing.
- `compiler/pe.fd:5739` `p_map_keys/values` store elements into the 24-byte Vec header (SIB scale ×1, data pointer stays NULL); `:5889` `p_map_clone` writes entries into the header; `:6236` `p_string_split` writes token pointers into `vec.len`; `:6338` `p_string_replace` handles one char and never grows.
- `src/pe.rs` (7537–7914): `map_get_or` always default; `string_contains`/`ends_with` always true; `trim/replace/upper/lower/repeat` return input; `split` empty; `find/rfind` 0; `p_panic` (5482) exits without a message.
- `compiler/pe.fd:3817` `p_to_str_float` uses `cvttsd2si`: NaN/Inf/≥2⁶³ print as INT64_MIN.
- `src/compiler.rs:1608–1622` runs the optimizer for `emit`/`build` and discards the result, so `-O` is a no-op on that path.

### P0-23. `select` without `default` doesn't block — **PLAUSIBLE**, M
- `src/lower.rs:2614`. Falls through when no channel is ready; a sent value equal to `i64::MIN+1` is treated as "not ready".

### P0-24. Field assignment silently dropped — **PLAUSIBLE**, S
- `src/lower.rs:~2366`: if the struct type or field can't be resolved, or the target is a `const`, no store is emitted and the RHS isn't evaluated. Root cause of P0-4. Emit an error.

### P0-25. Closure captures mis-typed / missed — **PLAUSIBLE**, S–M
- `src/lower.rs:~6488` captured params are always `I64` (TODO comment) → f64/str/struct captures miscompile. `:~6750` `collect_free_vars` inside `TryBlock` skips if/while/for/match, so captures are missed.

### P0-26. `@linear` alias analysis is disabled by a hard-coded `false` — **CONFIRMED**, S
- `compiler/opt.fd:5814–5816`.

### P1-3. Stage-1 self-hosted compiler crashes; the fixpoint claim is not reproducible from this tree — **VERIFIED** (at `d8b3044`; re-run after `3cdf0fc`, which changed `interp.fd`/`lower.fd`/`pe.fd` heavily)

### P1-4. C backend emits `alloca` per loop iteration — **CONFIRMED** (in generated C), M
- Every `var` inside a loop body lowers to `alloca(8); memset(...)` at the point of declaration, inside the loop. On Windows' 1 MB default stack a loop of ~100k iterations with a few locals will overflow; it also blocks optimisation. A 2M-iteration probe with two locals happened to survive under `zig cc -O2` (hoisted), but `-O0`/MSVC `/Od` will not. Hoist allocas to function entry (the IR already has the alloca list).

### P1-5. `runtime_linux.fd` process/env stubs — **CONFIRMED** (TODO lines), M
