# 0008: Contiguous data

- **Status:** proposed
- **Decision:** (pending)

## Problem

Fid's ownership heap (0004) is correct and safe, and it is what makes 403
stdlib modules — TLS, QUIC, databases — natural to write. But its layouts
pay three costs on pointer- and record-heavy data, measured by the layout
benchmarks in `bench/contig/` (benchmark programs ported from third-party
suites, each attributed at its head):

1. **Worst-case enum slots.** An enum value occupies `1 + max payload`
   words whatever variant it holds; `bench/contig/sexp.fd`'s `Sexp` node is
   3 words + tag (24 bytes) plus a heap string per symbol, where the
   record itself needs only 4..17 bytes with the text inline.
2. **Every dynamic value is a pointer away.** A `Vec<str>` is 1 + N heap
   blocks each carrying a counted-string header; a record with variable
   parts is a struct of handles, not a run of bytes. Words counted in a
   `HashMap<str, i64>` copies every key (`bench/contig/words.fd`).
3. **Serialization is a pass, not a property.** Structures of pointers
   need a serializer and a parser; a structure of relative links would be
   its own file format.

None of this is fixable by tuning: the costs are the layout.

## Change

Three opt-in additions, one memory-model piece and two comptime pieces,
each usable alone. They add to 0004; they do not replace it.

### 1. Variant-sized enum arrays: `Vec<E..>`

`Vec<E..>` (dot-dot after the enum name) stores each element at exactly
its variant's word count, sequential, iterate-only:

```
enum Shape { Circle(f64), Rect(f64, f64), Dot }
var packed: Vec<Shape..> = Vec::new();
packed.push(Shape::Circle(1.0));        // 1 word + tag, not 3 words + tag
for i in 0..packed.len() {              // iteration only
    match packed.get(i) { ... }         // bounds-checked, tag-read access
}
```

- Indexing stays available on plain `Vec<E>` (the fixed-mode array); the
  sequential form trades indexing for size.
- A variant's payload is read by address (`vec_ld`), as 0004's inline
  structs already are; the element code encodes the variant *and* its
  length: `code = 16 + Σ(variant_word_counts so far) + v` is not needed —
  the tag word is the first word, and the code becomes `16 + v` with the
  length read from a per-enum constant table. Details in Implementation.
- Overwriting an element with a different variant is an error (checked);
  a sequential array is built, not edited.

### 2. Region-stable arrays (0005 completion)

Finish proposal 0005's per-task arenas and add the invariant that makes
them sing: **at most one resizable value grows per arena region at
a time, and it is on top**, so growth is a pointer bump and references
into it never invalidate:

```
region pool {
    var nodes: Vec<Node..> = Vec::new();      // the region's top resizable
    let first = nodes.push_ref(Node { ... }); // a reference, not an index
    for ... { nodes.push(...); }              // a million pushes
    first.weight = 9.5;                       // still valid: nothing moved
}
```

- `push_ref` returns `&T` into the buffer, rooted at the region — the
  borrow checker's existing region roots (0005) bound its lifetime.
- Nothing is freed element-wise: region exit is one store (already 0005).
- This is OP29's arena with the one-resizable-on-top rule, which is
  what removes both the reallocation and the capacity slack.

### 3. Comptime flat codecs: `flat` on a contiguous type

For a type that is one buffer under 1+2 (a `Vec<E..>`, or a struct whose
fields are all inline), comptime generates its wire form — self-relative
4-byte links included — and its verifier:

```
@flat struct Node { key: i64, left: Node&<u32>?, right: Node&<u32>? }

val bytes: Vec<i64> = flat_bytes(tree);        // one write of the buffer
val back: OptNodeTree = flat_parse(bytes);     // verifies tags, lengths,
                                               // every link; None on a bad one
```

- `flat_bytes`/`flat_parse` are generated by `comptime gen` over the
  annotation reflection added Nov 21 (`field_names_of`, `field_types`,
  `field_annotations`): the generator walks fields, emits the link table,
  and the verifier checks each offset lands inside the buffer on the
  right tag — a verified loader derived from reflection rather than
  hand-written per type.
- A `@secret` field is refused by `flat_bytes` unless the call site is
  also `@secret`-authorized: the info-flow check rides along.

## What it breaks

Nothing existing. Each piece is new syntax on new values (`Vec<E..>`,
`push_ref` inside a region, `@flat`); the only new rejections are on the
new forms themselves (indexing a `Vec<E..>`, overwriting a variant,
`flat_bytes` of a type with a heap field). No edition needed.

## Alternatives

- **A no-heap memory model** (data stacks only). Rejected: it breaks the
  259K-line stdlib's shape (every `str` a heap value), and its costs — no
  growable data across recursive calls, no indexing of variable-size
  data, whole-program compilation only — are paid everywhere, not just
  where contiguous data wins.
- **Index-arenas by convention** (`Vec` + `i64` indices, the idiomatic
  port in `bench/contig/sexp.fd`). Kept as the fallback and the comparison
  row; 0008 makes the convention checked (typed links) and the buffer
  variant-sized.
- **Serialization as a derive only** (`@derive(Serialize)`, stdlib). Kept
  for JSON-shaped data; `flat` is for the case where the layout *is* the
  format.

## Implementation

All in `compiler/*.fd`; the Rust bootstrap needs nothing (fidesc is
frozen; the C it generates for these constructs is ordinary C).

1. **`Vec<E..>`** — parser: `..` after an enum in a `Vec<...>` element
   type (a new `Type::VariantArray(E)` or a flag on `Generic`); lower.fd:
   element codes per variant from the enum's payload table (`vec_ld` by
   address already handles variable-size codes — 0004's `code - 15` rule
   becomes a per-variant table lookup); typechecker: reject `v[i]` and
   variant-changing `set`; borrowck: nothing new. Behind
   `FID_CONTIGUOUS=1` until the suite is green, then on.
2. **Region-stable arrays** — finish 0005's `FID_REGION_ARENA` on the
   native runtimes (C exists; pe_runtime/linux_runtime do not), add the
   one-resizable-on-top rule to the region checker (a static check: the
   region's resizables form a stack), `push_ref` returns `&T` with the
   region as root. `scripts/region-check.sh` grows a stable-ref case.
3. **`@flat`** — a comptime generator (comptime_eval.fd `gen` blocks over
   `field_*_of`) writing `flat_bytes_<T>`/`flat_parse_<T>`; the link
   verifier is generated code, so it carries source spans. Gate:
   `bench/contig` round-trips plus a hostile-bytes test (corrupt every
   byte position once; every corruption is None or a good value).

The layout benchmarks (`bench/contig/`) are the acceptance gate for all
three: sum stays a dead heat; words and sexp are the rows that must move.
The remaining ports land one per fix they motivate.

## Related work

Variant-sized sequential data, arena-allocated graphs with stable
references, and verified flat serialization are established ideas; this
proposal is Fid's take, fitted to 0004's ownership heap:

- Index-arena graphs (`Vec` + `u32` indices) are the recommended shape in
  Rust communities for pointer-heavy data; 0008's typed links are the
  checked version of that convention.
- Systems languages with data-stack memory models (no heap at all) prove
  the layout wins of inline variable-size data and narrow links; the
  Alternatives section says why Fid keeps its heap instead.
- Serialization that verifies before bytes become values is standard
  practice for wire formats; `@flat` moves it from a hand-written parser
  per type to comptime generation.

The `bench/contig/` programs are ports of one third-party suite
(github.com/aardappel/goose, Apache-2.0; each file names its source).
They are measurements of Fid's layouts on data shapes that suite chose,
not a claim about its compiler.

## Companion (separate proposal when taken)

Compile-time function values (a block literal as a generic parameter,
monomorphized, non-escaping — `xs.filter() { it > 0 }` compiles to the
loop) fit our 0002 generics + inline cost model; it is a contained
addition and does not need this proposal's layout work.
