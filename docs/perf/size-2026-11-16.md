# Binary size, startup and peak memory (BM7), first recorded run

Roadmap: docs/roadmap/competitive-roadmap.md BM7. Made by `bench/size.sh`
(every program of `bench/size/` and `bench/fides/`, every language), on
2026-11-16, Windows 11 x64 (one machine, not quiet: other sessions were
running), with `FID=` a one-stage `fid` built Nov 15 (not a release
bootstrap). Rivals as `bench/run.sh` builds them: `rustc -C opt-level=3`,
`zig build-exe -O ReleaseFast` (Zig 0.16), `zig c++ -O2`, `go build`. No
GCC on this machine. Zig has no `hashmap` program.

Startup is from a second run (`bench/size.sh hello`), after the timing moved
into `bench/peakmem.py`: the first run timed with `date` in Git Bash and
measured ~130 ms of shell overhead for every language.

## Reading it

- Fides native (`fid emit`, pe_ir) makes the smallest executables here:
  33 KB for hello, against 123 KB (Rust) to 2.4 MB (Go). Through C the
  runtime is linked whole (410 KB).
- Peak memory is at the rivals' level. `hashmap` (one million string keys)
  uses 115 MB, more than C++ (79 MB) and Go (101 MB), less than Rust
  (132 MB). `sieve`'s C++ uses `std::vector<bool>` (bits), the others a byte
  per entry: 6.7 MB against ~23 MB.
- One run on one machine; BM8 (several runs, the spread, Linux) is not done.
