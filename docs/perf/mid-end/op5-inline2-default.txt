## Why: inline2 copied core's Vec_get/Vec_set/Vec_push/Vec_len (and other
## runtime functions) into the loops that call them
bench/fides/sieve.fd, FID_IROPT_STATS=1:
  inline2 off: iropt instructions 4647 -> 3987, run 482-681 ms
  inline2 on:  iropt instructions 10422 -> 8893, run 1133-1269 ms
emit --nat, FID_NAT_DUMP=main: main after selection 324 operations (off),
  796 (on); calls 54 (off), 161 (on).
test_midend_inline2_vecfast.fd (main calls only Vec_* and println), --nat:
  main 745 operations (off), 1706 (on); run 382 ms vs 518 ms.
pe_ir and nat_ir lower those calls themselves (a load or store with a fast
path), checks.fd proves their bounds checks away in counted loops, and a
Vec_* call goes to pe_runtime (pe_runtime_alias_target); core's body in
their place is a generic element-code dispatch with its own checks.
