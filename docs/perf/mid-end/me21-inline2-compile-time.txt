## What it says
- iropt's time grows faster than the instructions inlining adds: promote
  and iv grow 4-30x for 1.7-2.5x the instructions, so they are worse than
  linear in a function's size. Inlining fewer, smaller copies into big
  callers matters more than the total: IME_CALLER_MAX (4000) and the
  once-called size (IME_INLINE_ONCE_MAX, 400, not charged to the growth
  budget) are the limits to tune first (tests/tooling/inline2-tune.sh's
  settings start with caller=2000, caller=1500,once=200).
- inline2 itself took 0.66-2.5 s: each site inlined made its caller be
  scanned again from the first block, and every call site weighed copied
  the callee and walked it (ime_size, ime_callee_ok) again.

## Changed (Nov 17, compiler/iropt_me.fd)
- ime_inline_function goes on at the block after the site it inlined
  instead of the first block (FID_IROPT_OFF=inlinescan: the old rescan,
  to compare); the sites inlined and their order are the same (every call
  before it was refused, and what refused it only tightens).
- each callee's size and ime_callee_ok are found once (`memo`, forgotten
  when the function changes) and the callee is copied only when a site is
  inlined; the caller's size is found again only after a site is inlined.
- the limits are read once per build from FID_INLINE2_LIMITS (defaults:
  the constants), so one compiler can be tuned: tests/tooling/inline2-tune.sh.
- FID_IROPT_STATS=1 prints `iropt: inline2 N sites (O once, M multi),
  charged C of A, refused R by growth, Z by caller size, weighed W`.

## To measure with the final compiler ($FID)
  FID=$FID bash tests/tooling/inline2-limits-check.sh tests/bootstrap/test_matrix_mul.fd tests/bootstrap/test_lib_bigint.fd tests/bootstrap/test_generics_full.fd tests/bootstrap/test_hashmap.fd

## Final measurement (Nov 27, build/me20-fid-opt/fid-dev.exe)
All five commands above were run with the final compiler. The bottom-up
scan check passes on every program; test_lib_bigint resumes with the same
sites as a full rescan and weighs 1236 calls instead of 2927. The serial
me-measure run over the 13 ME20 programs has 0 output differences:
instructions 56614 on vs 51637 off (109.6%), iropt 6780 vs 6667 ms
(101.7%), whole builds 25408 vs 25054 ms (101.4%); the per-program table is
docs/perf/mid-end/me20-inline2.txt. inline2-tune.sh exits 0 and the default
limits are OK (docs/perf/mid-end/me20-inline2-tune.txt).
