WP7 (envtrim), WP14 (spec), WP15 (deadf) on by default; WP10 (readcse)
=====================================================================
llvm-roadmap Track WP. Nov 17. Code in compiler/iropt.fd, compiler/ir.fd,
compiler/checks.fd; check: tests/tooling/wp-defaults-check.sh.

What changed
------------
envtrim (WP7), iropt.fd iropt_native: `on_envtrim = iro_pass_on("envtrim")`
  (was also `ime_on`, opt-in). FID_IROPT_OFF=envtrim turns it off.
  - The exclusions are one table shared with WP6 (iro_conv_pinned,
    iro_conv_free; iro_conv_mark and iro_env_trim both use them). Before,
    each was a list scan per function (envtrim cost 795 ms of a 5.4 s
    iropt on test_brotli with the -O0 compiler of Nov 16).
  - Two callers the pass could miss are excluded now:
    * core's vec_buf_alloc: nat_ir's vector loops (ng_simd_call, OP21:
      p_simd_* and the simd module's simd_lanes_*_i64) call it by name
      with a null env in the first register. Trimmed, its `bytes` would
      read that 0 (a 24-byte block written n words long). ir.fd
      ir_dfe_root names it, so envtrim, WP6 and deadf all keep it.
    * functions the module's data names (ir.fd ir_data_named_fns: a string
      constant or a global's string initializer equal to a function name):
      `var g_entry: str = "triple"; task_go(g_entry, 7)` starts `triple`
      by name with the env slot first. Also excluded from LF10's
      parameter ranges (checks.fd peir_prm_internal).
  - FID_IROPT_STATS=1 prints "iropt: envtrim N calls".

spec (WP14), iropt.fd iro_specialize: `on_spec = iro_pass_on("spec")`.
  - Only call sites in functions main reaches count, and each clone is
    added to `reach`. Before, the clones were made after `reach` was
    computed, so the per-function passes skipped them as unreached: spec
    cloned and redirected but folded nothing (the Nov 16 measurement:
    "same instructions, +2.6 s of iropt" on test_counted_loop).
  - Linear: each candidate's call sites are recorded once (function,
    instruction, the constants passed), linked per candidate; weighing
    (iro_spec_site_weights, one loop tree per function) and redirecting
    visit only those sites. Before, every mixed parameter and every clone
    rescanned every instruction of the module. The clones and their order
    are what the old code chose, given the same sites.

deadf (WP15), iropt.fd: `if has_main && iro_pass_on("deadf")`.
  - ir.fd pe_ir_reachable_from: a table for the seen set and one scan per
    dyn method (was pe_strs_contains on a list, and a module scan per
    DynCall); pe_sort_strs is a merge sort (was insertion sort; same order);
    IrModule_dead_function_elimination keeps the reachable set in a table.
    deadf cost 1.4 s on hello at -O0 (driver-2-6's profile, Nov 17).
    pe_ir_reachable_from is also what iropt's `reach`, pe_ir and nat_ir
    use, so every emit gains from it.
  - Roots: also ir_data_named_fns (as pe88 in main.fd roots them).
  - Dead globals: a global an inline-assembly template names stays.
  - FID_IROPT_STATS=1 always prints "iropt: dead functions N, dead
    globals M" (was only when N or M > 0).

readcse (WP10): on by default since OP25 (compiler/rules.fd g_ru_readcse,
  rules_run; FID_NAT_OFF=readcse or FID_IROPT_OFF=readcse turns it off);
  tests/tooling/op25-check.sh checks it does something and runs the suite.

Found while doing this, not fixed (other groups' files)
------------------------------------------------------
A task entry named only by a global's string initializer
(`var g: str = "f"; task_go(g, 1)`) panics "task: no such function"
natively with every pass off (pe_ir named_fns comes from the strings the
code uses, nat_ir's named_seen from ConstStr instructions). The mid-end
now keeps such a function and its convention, so the backends can add
those names to their tables.
