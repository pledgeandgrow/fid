## RL13: what was added

- **Another host on one machine** (scripts/verify/repro.sh, `HOSTSIM=1`,
  the default). The second build of each program now also reads the stdlib
  from another, longer path (`FID_HOME`; both sides get a copy of one
  snapshot of `stdlib/`, so another session editing it during the run
  cannot make them differ), and runs as another user, host name, home,
  time zone (`TZ=Asia/Kolkata`) and locale (`de_DE.UTF-8`). Before, both
  builds read the same `FID_HOME` with the same environment, so a
  stdlib path, a user name or a clock zone written into an output would
  only have shown on a second host.
- **Worker threads** (`PAR="4"`, the default). Each program's
  host-independent outputs (dump-c, the Linux images) and `emit --nat` are
  built again with `FID_NAT_PAR=4 FID_PAR=4` (the machine layer's parallel
  emission, nat_ir.fd `ng_par_workers`; the parallel checks, borrowck.fd /
  escape.fd / secrecy.fd / lexer.fd) and compared with the serial build: a
  host with more cores, or a CI that sets them, must get the same bytes.
- **Where two builds differ** (new scripts/verify/bin-diff-locate.py).
  repro.sh runs it under every DIFFERENT line: per PE or ELF section the
  number of differing bytes, the first runs with their address and, in an
  ELF, the function holding them (from `.symtab`); for generated C the
  first differing lines and the C function each is in.
- **Two hosts, one command** (new scripts/verify/repro-hosts.sh, on
  Windows with WSL): repro.sh with `MANIFEST=` on Windows, then on Linux
  under WSL in WSL's own file system (`~/fid-repro-hosts`, so the paths
  are another host's, not `/mnt/c`), with a Linux fid (`FID_LINUX`, or
  built first with `LINUX_BUILD=cc|emit`), then `repro.sh --compare`;
  outputs that only one host built are named too. `COMPILER=1` adds the C
  of compiler/main.fd to both manifests. `$OUT/record.txt` keeps the date,
  commit, both compilers' hashes and each step's result.
- **TREE=<dir>** (repro.sh): programs that `use compiler::<m>` (the
  tests/nattools/*_unit.fd) get `<dir>/compiler` beside each copy.
- **The check of all of it** (new tests/tooling/rl13-repro-check.sh),
  with stand-in compilers (shell scripts), about 2.5 minutes, no build:
  a clean stand-in is reproducible; one that writes `FID_HOME` into its C,
  or the user and zone into its images, is caught with `HOSTSIM=1` and
  not with `HOSTSIM=0` (so the check fails without this change); one that
  writes `FID_NAT_PAR` into its images is caught by `PAR=4` only; one with
  the clock in its output is always caught; the location follows a
  difference; the manifest holds the C and the Linux image; `--compare`
  exits 0 on equal manifests and 1 on different ones; and repro-hosts.sh
  with a clean stand-in on Windows and in WSL says "hosts agree on all 2
  outputs" (exit 0), with one that writes `uname -s` into its C "hosts
  differ on 1 of 2 outputs" (exit 1). Result today: **0 wrong** (14
  verdicts).

The map-order half of RL13 needs no new code: the compiler walks maps only
through `HashMap_keys`/`HashMap_values` (no compiler module calls a slot
walk; the four `hm_*` names in typechecker.fd are its own functions), and
both sort the keys (stdlib/core.fd "Floods"); a map that reseeds with a
random seed still gives the same `keys()` order, which
tests/bootstrap/test_stdlib_hashmap_flood.fd checks ("int keys sorted ok").

## RL14: what was added

- scripts/native-fixpoint.sh: when stage 2 != stage 3, the drift is
  located (scripts/verify/bin-diff-locate.py: sections, and functions on
  Linux) into `$OUT/drift.txt` and the first lines are printed;
  `STAGE4=1` builds stage 4 with stage 3 and says which kind of drift it
  is: stage 3 == stage 4 ("stages 2 and 3 compile alike; stage 1 compiles
  differently from them": the C-built stage 1 and the emit-built stages
  disagree, a miscompile on one of the two paths) or stage 3 != stage 4
  ("the output does not depend on the source alone": nondeterminism).
- scripts/native-fixpoint-check.sh: a `settle` stand-in (stage 1 adds a
  line the built stages leave out) checked with `STAGE4=1` (exit 2, "stage
  3 == stage 4"), the `drift` stand-in with `STAGE4=1` ("stage 3 != stage 4
  too") and the location in drift.txt. Result: **0 wrong** (10 verdicts).

## RL14: runs

`fid emit compiler/main.fd` is a compiler build, so native-fixpoint.sh was
not run on any backend. What can be run without it is the determinism half
of the fixpoint on compiler code: the compiler's own front end
(tests/nattools/selfhost_front_unit.fd: compiler/token, lexer, ast and
parser from a HEAD snapshot, with HEAD's stdlib, as stage 0 needs) built
twice by each backend, through repro.sh with `TREE=` and `HOSTSIM=1`,
`PAR=4`:

    FID_HOME=<head> TREE=<head> NAT_TARGETS=x86_64-linux FID=<stage0> WORK=… \
        bash scripts/verify/repro.sh tests/nattools/selfhost_front_unit.fd

**8 of 8 outputs reproducible** (7.7 minutes): dump-c (9,667,507 bytes of
C), emit through pe_ir (1,361,715 bytes), ccompile (1,098,240), the
x86_64-linux image (1,215,152) and `emit --nat` (1,122,493), each the same
bytes from two directories with another stdlib path, user, zone and
locale, and the C, the Linux image and the `--nat` image the same with 4
workers. So on about 15,600 lines of the compiler's own code (plus core and
the runtime), pe_ir and the machine layer gave the same bytes for the same
input: no sign yet of the nondeterminism that would make stage 2 and stage 3
differ. This is not the fixpoint: it says nothing of whether the
emit-built compiler compiles like the C-built one.

Known before the run (isel agent, Nov 18): a compiler front end built by
`fid emit` crashed in its parser on pe_ir and `--nat` until the mid-end's
`ime_sra` is fixed (its needsOther); with the fix not in, stage 2 of
native-fixpoint.sh is expected to fail its `run hello.fd` (exit 1) before
any stage 2 / stage 3 comparison.
