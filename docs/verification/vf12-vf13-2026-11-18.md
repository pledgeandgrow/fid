# VF12 and VF13: reproducible builds and the clean-tree bootstrap, Nov 18, 2026

**Compiler**: the stage 0 of Nov 16 (`scratchpad/ws/stage0.exe`), Windows
x64, `CC="zig cc"` (zig 0.16.0), with the working tree's stdlib. It was
built from that day's working tree, so it holds the R1 fix of
compiler/main.fd (`repro_win_flags`, `repro_env_prefix`: the binary has

ran at the same time. This batch may not build the compiler, so the
`COMPILER=1` run and the clean-tree bootstrap were not run (below).

own TEMP, two seconds apart, `FIDES_NO_CACHE=1` (what
scripts/driver-goals-check.sh's VF12 check does):

| Build | Result |
|-------|--------|
| default (R1 on) | the same 309,760 bytes; no `.pdb` |
| `FIDES_NO_REPRO=1` (R1 off) | 422,912 bytes each, **20 bytes differ** (offsets 129-132, the PE time stamp, and the debug directory's PDB GUID near 405,509); a `.pdb` beside each |

So R1 holds and the check would fail without it.

## VF12: scripts/verify/repro.sh on Windows

    FID=<stage0> WORK=… MANIFEST=m-win.txt bash scripts/verify/repro.sh \
        tests/bootstrap/hello.fd tests/bootstrap/test_struct_eq.fd \
        tests/bootstrap/test_closure.fd tests/bootstrap/test_hashmap.fd

Outputs per program: `dump-c` text, `emit` (pe_ir), `ccompile`, `emit
--target x86_64-linux / aarch64-linux / riscv64-linux` (the machine layer),
`emit --nat`.

First run (the script as it was: each copy built from the project root by
its absolute path): **16 of 28** reproducible. `dump-c`, `emit`, `ccompile`
and `emit --nat` were the same bytes for all four programs; every Linux
image differed (24,786-35,205 bytes). Cause **R2**: the Linux images carry
DWARF, and its compile unit's `DW_AT_name` (and the `.debug_line` file
table) is the source path as given on the command line
(compiler/nat_enc.fd `nat_dwarf_build`, `nat_debug_line_at`), here
`C:/…/repro/a/hello/hello.fd` against `C:/…/repro/bb_longer_path/hello/…`;
its length moves every later section, so the section-header offset (byte
41) changes too.

repro.sh now builds each copy from its own directory by its file name, with
the stdlib from `FID_HOME` (default the project root), as a user builds a
program; `ABSPATH=1` keeps the old way and shows R2. Second run:
**28 of 28** reproducible (hello: C 1,319,121 bytes, emit 46,296, cc
339,456, x86_64-linux 182,296, aarch64-linux 190,552, riscv64-linux
186,464, nat 213,858). The 16 host-independent outputs (C and the Linux
images) are in the manifest; the C hashes of both runs are equal, the
Linux images not (the path in their DWARF): `repro.sh --compare` of the
two manifests says "hosts differ on 12 of 16 outputs", all Linux images.

R2 stays open in the compiler (miscompile-log.md): a build given an
absolute path, or the same relative path from a different project layout on
another host, still writes that path into the image. The fix (nat_enc.fd)
is to write the main file's name relative to its own directory unless
`--debug`, or to take a prefix map.

## VF13: scripts/verify/clean-bootstrap.sh

Not run (it is a cargo build and three compiler stages). What a clean tree
lacks was checked without building, and the script fixed for it:

- **Imports of files that were never committed.** compiler/main.fd of the
  working tree imports eight modules git does not track (build_info,
  disasm, image_writer, mir, nat_thumb, pdb, ssa, tv) and stdlib/ has 234
  untracked files: a HEAD archive is consistent (HEAD's main.fd does not
  import them), a `--worktree` copy has them. The script now checks, before
  the long steps, that every `use compiler::m` and `use m` of the tree's
  compiler/ and stdlib/ has its file (comments skipped; `tls` is
  tls_windows/tls_unix) and stops with the list. Checked: the HEAD archive
  and the working tree pass; a tree with `use compiler::gone; use
  nosuchmod;` fails naming both.
- **The checkout leaking in.** fid reads `./stdlib` first, then
  `FID_HOME`, and keeps its import and AST caches in TEMP: the script now
  unsets `FID_HOME`, `FID_LIB_PATH` and the cache variables, points
  TEMP/TMP/TMPDIR at a fresh `<out>/tmp` and sets `FIDES_NO_CACHE=1`.
- **`--worktree` with a deleted tracked file**: `git ls-files -c` still
  lists it and tar stopped; it is skipped now (`--ignore-failed-read`).
- **The record**: `<out>/record.txt` has the date, host, commit (and
  whether the tree had changes), CC, stage 0, the load, each stage's line
  from bootstrap.log, the fixpoint line and the result.

Dry runs with `STAGE0=/usr/bin/false` (no build: stage 1 fails at once):
the HEAD archive (75 MB) in 12 s and the working tree in 50 s, both past
the import check, record written.

Open for the real run: no stage 0 is pinned (no `release/stage0/fid.exe`,
no `scripts/stage0.sha256`), so a clean tree starts cold from the Rust
compiler, which is frozen; whether `fidesc` still compiles today's
compiler/ and core.fd (generics, the region hooks) is what the first run
shows. If it does not, the clean path needs a pinned stage 0 (`PIN=1
scripts/bootstrap.sh`, docs/reference/stability.md).
