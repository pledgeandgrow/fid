# RL9 and RL25: writer fixes and the C-ABI lanes (Nov 17)

Own-backend roadmap (docs/roadmap/llvm-roadmap.md) RL9 and RL25. What the
two new checks do, and what they showed with the stage-0 compiler (the
compiler of this morning; none of today's source changes are in it). The
final build of Nov 17 is to be checked with the same commands.

## RL9: the two writer bugs image-lint found

docs/verification/backend-checks.md lists them:

1. A dynamically linked ELF executable of the machine layer had PT_DYNAMIC
   but no SHT_DYNAMIC section (readelf: "Error: no .dynamic section in the
   dynamic segment"). Fixed in compiler/nat_enc.fd `nat_elf_debug_sections`
   (TG13, this run): `.interp`, `.dynstr` (from DT_STRTAB / DT_STRSZ, read
   by `nat_elf_dyn_value`) and `.dynamic` (SHT_DYNAMIC, entry size 16,
   `sh_link` .dynstr) at the addresses and file offsets of PT_INTERP and
   PT_DYNAMIC.
2. A COFF object of `fid codegen --coff` gave every symbol name longer than
   8 bytes string-table offset 0 (`symbol_name_map_lookup` found none).
   Fixed by TG13: compiler/coff.fd `CoffEmitter_build_coff` writes its
   symbols through compiler/image_writer.fd `img_coff_symbols`, which puts
   each long name in the string table and its offset in the record.

Unit tests of the writers themselves: tests/nattools/image_writer_unit.fd
("elf debug ldyn .interp/.dynamic/.dynstr ok") and
tests/nattools/image_writer_obj_unit.fd ("coff ok": the long names
resolve).

New check on real programs, `bash tests/nattools/rl9_writer_fixes_check.sh
$FID`:

- `1 <target>`: tests/bootstrap/test_verify_abi_c_mixed.fd (libm's ldexp,
  frexp, modf and libc's strtod are bound at load time, so the image has
  PT_INTERP and PT_DYNAMIC) for x86_64-, aarch64- and riscv64-linux: a
  SHT_DYNAMIC section at PT_DYNAMIC's address and offset, `sh_link` a
  string table; scripts/image-lint.py clean; `readelf -W -a` (here or in
  WSL) without an error or a warning.
- `2 coff`: tests/nattools/rl9_coff_long_names.fd through `codegen --coff`:
  image-lint clean, every long name resolves, the two long function names
  and the 8-byte one are in the symbol table.

With the stage-0 compiler, as expected before the fixes:

```

FAIL 1 aarch64-linux: PT_DYNAMIC but no SHT_DYNAMIC section

```

(and `wsl readelf -W -l -S` on the x86-64 image: "readelf: Error: no

## RL25: both C-ABI tests on every lane

`bash tests/nattools/rl25_abi_lanes_check.sh $FID` builds
tests/bootstrap/test_verify_abi_c_records.fd and test_verify_abi_c_mixed.fd
on every lane this host can run (`c`, `pe`, `nat`, `native:<t>` and
`c:<t>` for the three Linux targets, `c:wasm32-wasi`) and compares each
run with the file's "Expected output:" block (the interpreter cannot call
qsort or ldexp, so scripts/cross-test.sh has no reference for these two).
It writes `$OUT/record.txt`. A dynamically linked Linux binary under
qemu-user without the target's glibc is SKIP (install libc6-arm64-cross /
libc6-riscv64-cross or set QEMU_LD_PREFIX).

With the stage-0 compiler (LANES="pe nat", plus single runs):

| lane | records | mixed |
|---|---|---|
| pe (`emit`, pe_ir) | PASS | PASS |
| nat (`emit --nat`) | PASS | build fails: "not available ...: ldexp, frexp, modf, strtod" |
| c (`ccompile`, zig cc) | not run | C error: "call to undeclared function 'p_ldexp_user'" (also frexp, modf, strtod, fmod) |
| c:wasm32-wasi | builds (earlier run) | the same C error |
| native:x86_64-linux | — | builds; at load ld.so fails (the stage-0 runtime imports nat_tls_set: TG15 hunk B) |

Why each failing cell fails, and where the fix is (none of it in the image
writers):

- `nat` mixed: on Windows the machine layer imports no C function the
  runtime does not define (compiler/nat_ir.fd `ng_ldyn_ok` refuses
  `g.win`). compiler/nat_enc.fd already has the import side (TG15:
  `nat_pe_dll_for` maps `link "m"` to ucrtbase.dll and the C library to
  msvcrt.dll; `nat_pe_win64_stub` moves the arguments to the Windows x64
  convention, a float to both xmm<j> and its integer register); the
  nat_ir.fd hunks that use them are in TG15's report (A, C, E, F). The
  records test passes on `nat` because qsort, bsearch, labs and memcmp are
  the runtime's own (stdlib/linux_runtime/sys.fd `pert_c_*`).
- `c` and `c:*` mixed: compiler/codegen_c.fd `sanitize_c_name` skips the
  names in `extern_func_names`, but nothing fills that list, so an
  `extern "C"` function named like a libc one (`fn ldexp`, no `as`) is
  called as `p_ldexp_user`, which nothing defines. The fix fills the list
  from `module.extern_decls` in `CCodeGen_generate`.
- macOS needs a Mac.

A gap the lanes do not show: the machine layer hands C the raw address of
a Fides function (nat_ir.fd `Inst::ConstFnRef`), whose convention takes
`__env` first. That works because the only C functions that call back
(qsort, bsearch) are the runtime's own; a callback passed to a real
imported C function would get its arguments one place off (and on
Windows in the wrong registers). An adapter per callback (as pe_ir's
`c_adapters` and the C path's `__c_fn_<f>`) is needed before such a call
can be allowed.
