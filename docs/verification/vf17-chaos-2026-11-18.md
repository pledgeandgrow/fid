# VF17 chaos tests: clock jumps and partitions (Nov 18)

Roadmap VF17 (competitive-roadmap, Track VF) asked for two more kinds of
chaos and a check of the Nov 7 findings C1-C5. This page records what was
added and the run of Nov 18. The table of findings is in
[miscompile-log.md](miscompile-log.md), "Runtime under failure".

## What was added

| File | What |
|------|------|
| `tests/verify/chaos.fd` | two modes. `fetch <host> <port> <path> <ms\|none>`: a GET whose connect (inside a `timeout(ms)` block, `p_co_connect`) and every read (`p_co_recv`) wait at most `ms`; with `none`, the transport of stdlib/http_client.fd (`p_net_connect`, blocking reads, no limit). `clock <case>`: six waits a clock jump must neither stretch nor cut short: `sleep` (1 s, outside tasks), `tasks` (three tasks waking by deadline at 300/600/900 ms), `timeout` (a 700 ms `timeout` block around a 4 s `task_sleep_cancellable`), `token` (`task_token_with_timeout(700)`), `cosleep` (a 700 ms `timeout` block around `task_sleep(4000)`), `waitfd` (`task_wait_read` of a silent socket, 700 ms) |
| `scripts/verify/clockjump.c` | an LD_PRELOAD library (libfaketime's idea, one scheduled jump): `CLOCKJUMP_AT_MS`, `CLOCKJUMP_BY_MS`, `CLOCKJUMP_CLOCK=realtime\|monotonic\|both`; replaces `clock_gettime`, `gettimeofday`, `time` |
| `scripts/verify/chaos_linux.py` | the Linux half, run in WSL by chaos.py (or by hand on Linux): `build` (gcc against glibc, so LD_PRELOAD reaches the program; the C is `fid dump-c tests/verify/chaos.fd`), `clock` (every case with no jump, the wall clock an hour forward, an hour back, and every clock an hour forward, 250 ms into the wait; `--faketime LIB` uses libfaketime for the wall-clock jumps), `partition` (below) |
| `scripts/verify/chaos.py` | `--clock`, `--partition` (both also under `--linux`), `--linux-nat` (full disk and out of memory on `emit --target x86_64-linux` too), `--faketime`, `--strict`, `--src`; a table of open findings (KNOWN): a failure of one prints `OPEN <id>` and fails the run only with `--strict`, a pass of one says the finding looks fixed; a new host scenario, "argument past the last" (C8); every other host scenario now passes three arguments so it measures what it names |
| `tests/verify/bugs/c8_emit_arg_at_past_last.fd` | C8: the program runs itself with one argument and asks for a second |

Partitions: `unshare -rn` (a user namespace: no root), a second network
namespace (`unshare -n`) joined by a veth pair (10.213.0.1 and .2), the
server in one, the chaos program in the other. A partition is an nftables
input rule in each namespace that drops every packet from the other side
(the sender is told nothing, as when a link between machines fails; `tc
netem` on the sender's own device would report the drop to TCP, so it is
only the fallback when nftables is missing). Healing deletes the rules.
Scenarios: no partition (the whole answer, 200,062 bytes); cut after the
first 8 KB with a 1.5 s read timeout; the same cut with no limit; a 2.5 s
cut, then healed (TCP resends; all of it arrives); a connect into a cut
inside a 1.5 s timeout block; a blocking connect into a cut.

## The run of Nov 18

the tree's compiler/ was not to be built in this task), with the tree's
stdlib. That stage 0 has neither the token slot (`p_task_token`,
`p_task_set_token`) nor `timeout` blocks, so it ran a copy of chaos.fd with

## C1-C5 checked

- C1 open: http_client's transport has no timeout anywhere (silent server,
  and now a partition mid-answer). stdlib/https.fd `fetch` reads with a 30 s
  limit; http_client should do the same (needsOther of this run).
- C2 and C3 were one bug, C8: chaos.fd reads `arg_at(3) ?? "0"` before every
  mode, and on emit `arg_at` past the last argument returns a wild pointer
  when there is at least one argument. Given a third argument, the emit
  driver reads a missing file and a directory as None and reports "Panic:
  Stack overflow"; the bug files c2/c3 (no arguments) pass on emit.
- C4 open: `p_file_append` (C runtime, and pe_runtime's `pert_file_append`
  by reading) ignores what `fputs` and `fclose` return.
- C5 partly fixed: exit 1 and a panic line, but the C runtime still calls
  `abort()`, so the panic names SIGABRT. chaos.py now requires a `Panic:`
  line that names memory.

## Validating with this run's compiler

```
python scripts/verify/chaos.py --fid $FID --linux --linux-nat --out build/chaos
```

Passing: every line PASS or OPEN with one of C1, C4, C5, C6, C7, C8 (exit
0); in particular `clock timeout`, `clock cosleep` and `connect into a
partition, timeout` PASS (the tree has timeout blocks), and the clock cases
under "no jump" and "all clocks +1h" all PASS. A FAIL line is a new finding.
A line that says a finding "looks fixed" means the table should be updated.

## Not covered

Clock jumps on Windows (they would mean changing the system time) and in
statically linked programs (fid's musl cross builds and the machine layer's
images do not load LD_PRELOAD; a time namespace offsets only the monotonic
clocks, and only at the start); libfaketime itself (not installed in this
WSL, no root to install it: `--faketime` is written and not run); a disk
that fills part-way through a write on Windows; partitions between real
machines (the veth pair is one kernel's TCP on both sides).
