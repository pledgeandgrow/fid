# RL10: random IR through the machine layer (Nov 17)

llvm-roadmap RL10: fuzz the IR -> machine code path with random IR, not
only random source, so backend bugs show without front-end limits.

## What the random IR holds

`fid ir-fuzz <seed>` builds a template program (compiler/ir_ser.fd
`irfuzz_template`) and, after lowering, replaces its functions by IR made
from the seed (`irfuzz_function`, `irfuzz_helper_function`). Nov 16 the IR
had i64 arithmetic (shifts, division by safe constants), if/else on
compares and counted loops, in stack slots. Nov 17 it also has:

| Part | Statements | IR it exercises |
|------|------------|-----------------|
| f64 arithmetic | `[5, e, a, fop, c]` w = f(v) op C; `[6, d, e, gop, g]` v = (w ± w) as i64, or w < w / w <= w as 1/0 | f64 stack slots (`Alloca F64`, f64 `Load`/`Store`), `IntToFloat`, `ConstFloat`, f64 `+ - * /`, `FloatToInt` (truncation), f64 compares feeding a branch |
| heap memory | `[7, a, ix, k]` store, `[8, d, ix, k]` load, at `(v[ix] + k) & 7` or the constant `k & 7` | `p_malloc` of 8 words, `BitCast` to `*i64`, `GetElemPtr` with constant and computed indexes, loads and stores through it, `p_free` before the return |
| calls between generated functions | `[9, d, h, a, b]` v = fz_h<h>(v, v) | direct calls with the null environment first, as the lowering makes them; fz_target calls fz_h0 and fz_h1, fz_h1 calls fz_h0 (acyclic, so the calls end) |

Every value stays defined: f(x) = ((x & 0xFFFFF) - 0x80000) as f64 is exact,
the f64 constants are binary fractions (0.5, 0.25, 3.25, -1.75, 2^20,
2^-7, 7.0, 3.0), so |w| < 2^40: never NaN, never out of the i64 range. The
result folds in every variable and every word of the buffer.

`irfuzz_eval` (via `irf_eval_unit`) works the printed value out from the
same descriptions. `irfuzz_unit_source` writes each function as Fid
source that computes the same (fz_target's buffer as a `Vec<i64>`); the
template holds fz_h0 and fz_h1 as that source, so a driver that replaces
only fz_target still calls functions of the known value, and
`irfuzz_install_helpers` replaces them by their random IR too (wired in
compiler/main.fd `irfuzz_install`: see "Open" below).

## Checks

| Check | What it shows | Run |
|-------|---------------|-----|
| `tests/bootstrap/test_irfuzz_kinds.fd` | the IR of seeds 4..7 holds each new kind (f64 slots, conversions, constants, arithmetic, compares; p_malloc/p_free, element addresses, heap loads and stores; calls target -> fz_h0/fz_h1 and fz_h1 -> fz_h0 only), every block ends in a terminator, `irfuzz_install_helpers` replaces both helpers, the value is one per seed | `$FID run tests/bootstrap/test_irfuzz_kinds.fd` |
| `tests/tooling/irfuzz-mirror-check.sh` | the evaluator agrees with the language: each seed's functions as source, run by `fid run`, print what `irf_eval_unit` says | `FID=$FID bash tests/tooling/irfuzz-mirror-check.sh 1 40` |
| `scripts/fuzz/fuzz_ir.sh` | the machine code agrees with the evaluator, per target | `FID=$FID TARGET=<t> [MIDEND=1] bash scripts/fuzz/fuzz_ir.sh 200 1` |
| `tests/tooling/irfuzz-targets.sh` | fuzz_ir.sh on x86_64-linux, aarch64-linux, riscv64-linux (WSL + qemu from Windows) and x86_64-windows (`--nat`), each without and with `--mid-end`; failing seeds kept in `tests/verify/bugs/irfuzz/` | `FID=$FID bash tests/tooling/irfuzz-targets.sh 200 1` |

is in `tests/verify/bugs/irfuzz/<target>[-mid]-<seed>.fir`, replayed with
`fid emit-ir <file> --target <target> [--mid-end]`, and gets an entry in
[miscompile-log.md](miscompile-log.md).
