# VF2, Nov 17 2026: the V1 class reduced, --ext2, a long run

Roadmap VF2 (docs/roadmap/competitive-roadmap.md): random programs, each
with an equivalent C program, built by Clang and GCC. This run did the three
things the entry had left: reduce the V1 class and file each cause, add
floats printed to a fixed precision, string slices and more enum matching to
the generator, and a long run.

Machine: the shared Windows 11 machine, busy (other sessions' compilers
running). Compiler: the Nov 16 one-stage build used by this run's agents
(`stage0.exe`, `fid 0.8.0-unstable`), with the stdlib of the HEAD commit
(Nov 15 23:40) as its home: the working tree's `stdlib/core.fd` already
calls `p_region_word` (regions freed in one step, another session's work),
which that compiler's interpreter does not have. A compiler finds `stdlib/`
in its current directory before `FID_HOME`, so the runs were made from that
home, not from the repository. C oracle: `zig cc` 0.16 (Clang) and GCC 15
in WSL (kali-linux), each at -O0 and -O2; the four builds agreed on every
program of every run below (0 oracle disagreements).

## 1. The V1 class (seeds 100–159 of Nov 7)

V1 was "spurious and missed overflow panics on run and emit" in 12 of the
60 programs of `gen_vs_c.py --seed 100` (Nov 7). With `--avoid none` the
generator gives the Nov 7 programs again (checked against the Nov 7
generator: same text for seeds 5, 100, 137). Rerun on the Nov 16 compiler:

- `--avoid none`, the nine V1 seeds: 100, 103, 136 and 154 now agree with
  C on run, ccompile, emit and `--nat`. 107, 113, 137 and 140 are rejected
  on every backend by M2 (a nested `if` value typed void), so on Nov 7
  their "panic" on run was a compile error read as exit 1.
- `--avoid nested-if-value` (M2 only; M1 casts kept), all 60 seeds: 6
  differ (log `--log`: 102, 120, 137, 140, 151, 157). By backend: run 3,
  ccompile 3, emit 5, `--nat` 4.

Each was reduced (`scripts/fuzz/reduce.py`, or by hand from the C oracle:
the C program's `panic` changed to print the helper that called it and its
operands, which names the first operation that should panic):

| Seed | Backends | Cause | Filed as |
|------|----------|-------|----------|
| 151 | all | `(2 << (s.f1 & 15)) - (s.f1 + s.f1)` on a u16: the literal 2 is not a u16, the shift is done wide (65536), the subtraction does not overflow | **V1a** `v1a_shl_literal_left_narrow.fd` |
| 140 | run, emit, `--nat` | `v1 as u16` of an i8 −64 stays −64 (should be 65472): `1 - 65472` should overflow | **V1b** `v1b_signed_to_unsigned_cast.fd` |
| 102 | emit | reduced to 13 lines (`reduce.py --bad emit --good ccompile`, 52 tries): `(0 - 1) as i32 as u32 > 0` is false (V1b, same width) and `~111u64 as i32` is 4294967184 (M7), so `a as i32 * 2` overflows | V1b + M7 |
| 120 | ccompile | `xs[xs.len()]` reads 0 instead of panicking: `xs[i]` lowers to the C runtime's `p_vec_get`, which returns NULL out of range | **V1c** `v1c_ccompile_vec_index_oob.fd` |
| 137 | emit, `--nat` | `59134u16 as i8` is 254, not −2 (a branch flips, `0 - 59134` is missed) | M7, now also on `--nat` |
| 157 | run, ccompile (M3); emit, `--nat` (M7) | println of a u64 ≥ 2^63 prints it signed; `228u64 as i8` stays 228 | M3, M7 |

So the V1 class is reduced: every program of it is explained by M1, M2,
M3, M7 or the three new causes V1a, V1b, V1c, each with a repro under
`tests/verify/bugs/` and a row in docs/verification/miscompile-log.md.
V1b is not stepped around by `--avoid` (only casts of one width are), so
it is behind most run/emit differences of the long run below.

## 2. The generator: --ext2, --jobs, --log

`scripts/fuzz/gen_vs_c.py --ext2` (implies `--ext`; its random numbers are
drawn only when it is on, so plain and `--ext` seeds give the same programs
as before, checked for seeds 1, 5, 9, 300, 309):

- floats printed to a fixed precision: each `--ext2` program has
  `fn ffix(x: f64) -> str` (three decimals, rounded half up through
  `(a * 1000.0 + 0.5) as i64`, `/`, `%` and `int_to_str`); C prints the
  same digits with `"%s%lld.%03lld"` from the same operations, each in its
  own `noinline` function under `FP_CONTRACT OFF`. Printed: fa, fb,
  `fa + fb`, `fa - fb`, `(fa * fb) / 1000000.0`, `(x as f64) / 7.0` of
  i8/i16/i32 values, and fa, fb at the end. Every value given to `ffix` is
  within about 3.1e8, so the cast is in range (F-ftoi);
- strings: `str_slice(st, a, b)` with bounds masked or raw (negative and
  past the end are clamped as core's `str_slice` does; C's `sslice` does
  the same), `str_byte_at(st, (e & 1023) % str_len(st))`, `st == "lit"`,
  and an f-string `f"{st}<{v}>"` of an integer of any type but u64 (M3);
- enums: a `match en` with a `Sh::Two(x, y)` arm and a `_` arm.

`--jobs N` checks N seeds at once (each seed has its own files); `--log F`
appends `<seed> ok|differs|oracle <backends>` per seed and a summary line,
and the summary now gives the count per backend. `scripts/fuzz/
vf2_long_run.sh` runs the three kinds (plain, `--ext`, `--ext2`) with them
and writes `summary.md`.

`--avoid for-match-break` (on by default, as every `--avoid` entry): a
`for` body with a `break` and a `match` is written as the equal `while`
(V1d below).

`tests/bootstrap/test_verify_vf2_ffix.fd` checks `ffix` on 16 chosen values
against what C prints (passes on run, ccompile and emit with the Nov 16
compiler); `tests/tooling/vf2-ext2-check.sh` checks the generator (checks
1–3 pass without a compiler; 4–5 need one).

## 3. The long run: 1002 programs on `run`

    FID=<stage0> N=334 KINDS=plain,ext,ext2 BACKENDS=run JOBS=1 \
      bash scripts/fuzz/vf2_long_run.sh       (from the HEAD stdlib home)

| Kind | Seeds | Programs | Differ from C | C oracle disagrees | Time |
|------|-------|----------|---------------|--------------------|------|
| plain | 20000..20333 | 334 | 6 | 0 | 1135 s |
| --ext | 120000..120333 | 334 | 6 | 0 | 921 s |
| --ext2 | 220000..220333 | 334 | 7 | 0 | 862 s |

1002 programs, 19 differ on run (1.9%), every C build agreed. Only `run`
was compared in the long run: one compiler process at a time (this run's
rule, the tree being shared with other agents) makes `ccompile`, `emit`
and `--nat` about 10–15 s a program each, 4–5 hours more for 1000. The 17
differing seeds that the V1d avoidance does not change were rerun on run,
ccompile and emit (clang oracle):

| Backends that differ | Seeds | Cause |
|----------------------|-------|-------|
| run, emit (ccompile right) | 20109, 20122, 20226, 120221, 120275, 120333, 220050, 220121, 220304, 220317 | the pattern of V1b (run and the native backends wrong, the C path right); 20122 reduced (`reduce.py --bad run --good ccompile`, 83 tries, 10 lines): V1b, `(-63 as i16) as u32` stays −63 on run, so `v6 -= ...` adds 63 where C's u32 subtraction overflows |
| run, ccompile, emit | 20117, 220230 | **V1e**: `(9 as u32) % ((31 & 15) \| 1)` is typed i64; reduced by hand from the C oracle's first panic (`sub_u32(0, 5)`) |
| run, ccompile, emit | 20285, 120037, 120263, 220074 | the same family (literal typing, V1a/V1e): each has a literal-left shift or an all-literal divisor in the failing expression; not reduced one by one |
| run only | 20016 | V1b: reduced (`reduce.py --bad run --good emit`, 68 tries, 9 lines) to `15 < v9 as u16` with `v9: i8 = -26`, false on run (−26) and true in C (65510); emit happened to be right in this form |
| all (V1d) | 120083, 220332 | **V1d**: `break` in a `match` arm inside a `for` leaves only the match, on every backend; `v1d_for_match_break.fd`. With `--avoid for-match-break` both seeds agree with C on run |

None of the differences was traced to a float, string or enum operation:
in the rerun, `ccompile` printed exactly C's output (floats through `ffix`
and `(f * 1000.0) as i64`, strings, the enum) for every `--ext`/`--ext2`
seed of the "run, emit" group, and the differences on run and emit follow
the V1b pattern; the all-backend ones are V1d and V1e. A per-seed
reduction of the "run, emit" group was not done, so a second cause hidden
behind V1b there is not ruled out.
