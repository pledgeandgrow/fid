## Finding O1: gconst folds nothing, because of miscompile M26

`iro_const_globals` (compiler/iropt.fd, WP18) folded a global named
`LIMIT` (2 loads) but not one named `base` (0), in otherwise equal
programs. The IR showed why: core's `hm_set_hashed` has a local `var base`
and its assignments `base = ...` were lowered as `GlobalAddr("base")` +
`Store`, so phase 0 of gconst saw the user's global stored to. The cause
is in the lowering: `Stmt::Assign` (compiler/lower.fd) looks the target
up with `IrModule_get_global` before `Lowerer_lookup_alloca`, so any
assignment to a local that has the name of a global writes the global.
Reads look at the locals first. On every backend:

```fd
var base: i64 = 100;
fn shadow(c: bool) -> i64 { var base: i64 = 1; if c { base = base + 5; } return base; }
// shadow(true) is 1, not 6; the global becomes 6; one HashMap insert sets it to 262144
```

A global named like one of core's loop counters (`i`) hangs the program in
core's HashMap insert. Logged as M26 in [miscompile-log.md](miscompile-log.md);
repro `tests/verify/bugs/m26_assign_shadowed_global.fd`, test
`tests/bootstrap/test_verify_vf5_global_shadow.fd` (both fail until the
fix). The fix is in compiler/lower.fd (another group's file): in
`Stmt::Assign`, take the global path only when no local of the name exists.
With it gconst folds what it was meant to; `gconst-stored-folded` then has
something to break.

## Tests of the machine layer's passes (kill-switches.md, `FID_NAT_OFF`)

Each prints values that change when its pass is wrong; each passes on run,
ccompile, emit and `emit --nat` with the Nov 16 compiler.
`scripts/verify/nat-pass-reach.py` builds each with its passes off one at
a time and says whether the image changes (the pass is reached) and the
output does not; with `--mutants` it builds them under the machine layer's
run-time mutants (`FID_NAT_MUTATE`) too. Results on `--nat` (Windows):

| Test | Passes reached (image changed, same output) | Not reached on `--nat` | Run-time mutants |
|------|------|------|------|
| test_verify_nat_promote | promote | | |
| test_verify_nat_ipra | | ipra (also with 14 values live across calls; arghint, argfree, fcallee inert) | |
| test_verify_nat_coalesce | coalesce, livecoal | hint | split inert |
| test_verify_nat_remat | remat, weights | rematmov | |
| test_verify_nat_brfuse | brfuse | | brgap **killed**, tbz **killed**; brnot, brandor, brxblock inert |
| test_verify_nat_addshl | addshl, vecinline | | memop **killed**, ldop **killed**; ldext, rmw, memcmp inert |
| test_verify_nat_egraph (`FID_IROPT_OFF=fold,sccp,gvn,promote,branchfacts,licm,iv`) | egraph, forward, rules, purecse | | egfold, egident, ... not in this compiler |
| test_verify_nat_misc | lea, tailcall, retregs, xmmcache, mirfold, relax, peep, fold | leaf | isel **killed**, addi **killed**; iselimm, iselcc, iseldiv, shi inert |
| test_verify_nat_unchecked_fail | unchecked, coldpanic, vecinline | | |

ipra and leaf change nothing on `--nat` Windows here; whether they do on
the Linux targets is for the final build (`nat-pass-reach.py --target
x86_64-linux` and `aarch64-linux`).
